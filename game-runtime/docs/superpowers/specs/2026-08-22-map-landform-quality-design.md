# 百眼迷城 地貌精度与质感改造 设计

日期：2026-08-22
状态：已评审通过（§1–§5 逐节确认）
影响面：`packages/content`（权威高度场）、`packages/sim`（LoS/移动）、`apps/web/src/render`、C# 移植、golden fixtures

---

## 0. 问题陈述

对照参考项目（生物群系驱动的 3D 低多边形 MMO）的地图观感，当前实现的差距不在道具细节，而在**地貌本体缺席**。

现状量化：

| 维度 | 现状 | 问题 |
|---|---|---|
| 地图尺度 | 840m × 700m | — |
| 地形振幅 | `TERRAIN_AMPLITUDE_MM = 5_200` | 起伏比 **0.6%**（参考项目约 3–5%），本质是"有点疙瘩的平板" |
| 授权高台 | 3 处，顶高 3.5–4.0m | 山体全靠墙体棱柱假装 |
| 伏石圈 ×24 | `flattenAt(r=8.5m)` 纯压平，无 bowl | 地形上读不出 |
| 小怪巢穴 ×48 | bowl −0.52 ~ −0.90m | 下陷不足 1m，远看是平地上一撮道具 |
| Boss 巢穴（龙宫×5/精英×4） | **只压平，连 bowl 都没有** | 地形上完全读不出是 Boss 点 |
| 相机 | `OrthographicCamera`，俯角 38.9° | 正交投影下纵深、地平线、大气透视**物理上不可能出现** |

一句话：道具做得细，但一切发生在一块平板上，dressing 再多也撑不起质感。

## 0.1 已确认的约束（用户裁决）

1. **可以动权威高度场**，接受 geometry/fixtures/对拍重烧，**分两阶段**执行。
2. **视角一起靠拢**（正交 → 透视）。
3. 四条玩法底线不可破：**寻路全图连通**、**视线遮挡不能失控**、**出生点高度公平**、**伏石/安全圈机制不变**。
4. 路面坡度上限 **12%**。
5. LoS 阈值**先量化基线再敲定**，不拍脑袋。
6. 巢穴碗壁**做陡 + 授权坡道**；内环巢穴深 **−4.0m**；**三庭庭心不做地形下沉**。

## 0.2 方案选型

| 方案 | 结论 |
|---|---|
| A. 区域地貌骨架（宏观地貌层 + 波长约束） | **采纳** |
| B. 权威台地拼盘（扩 highlands 到 ~15 块） | 否决：读作"台地拼盘"，无有机感；其 ramps 手法被采纳为工具 |
| C. 离线侵蚀烘焙高度图 | 否决：新增大体量栅格资产，C# 必须同栅格，连通与公平全靠后处理补救，迭代慢 |

A 是唯一同时满足「有机地貌 + 四条底线可由设计保证 + C# 可移植（仍为无资产纯整数函数）」的路线。

## 1. 地貌模型与权威分层

### 1.1 高度合成顺序

```
h = macroRelief(x, z)            ← 新增：区域地貌层，±18m
  + wilderness(x, z)             ← 现有 fbm + ridge，振幅按区缩放 3~9m
  → 削填走廊（路网）               ← 现有 road stamp 升级
  → 出生台（含高程均衡）            ← 现有 pad 升级
  → 高台 / 三庭多边形压印           ← 现有，不变
  → POI 地貌（伏石 / 巢穴 / Boss）  ← 现有 features + bowls 升级
```

### 1.2 坡度由构造保证，不做后置钳制

后置坡度钳制需要全局信息，会破坏纯函数性质、难以移植到 C#。改用**波长下限**约束坡度：

> 正弦型地貌最大坡度 ≈ `振幅 × π / 波长`

取 **波长 ≥ 220m、宏观振幅 ≤ 18m** ⇒ 最大宏观坡度 ≈ 0.26 ≈ **14.6°**，天然可走、可闪现。陡面只由已授权的高台与边界崖产生，而高台自带坡道。

`terrain-height.ts` 因此保持为**无资产的整数纯函数**，C# 逐行照搬即可。这是选择方案 A 的核心收益。

### 1.3 七区地貌档案

对齐 `map-regions.ts` 中已有的真源区域设定：

| 区 | 设定 | 基准海拔 | 宏观振幅 | 地貌算子 |
|---|---|---:|---:|---|
| 龙脊渊 longji | 高台深潭 | +8m | 22m | ridge 主导（双脊）+ 深潭盆地 |
| 蛛丝峡 zhusi | 双折峡谷 | −6m | 16m | 两条平行谷线，谷底走廊 |
| 迷魂田 mihun | 深穴群 | −3m | 9m | 多个浅盆叠加 |
| 烬水市 jinshui | 高价值中圈 | +1m | 7m | 缓丘 |
| 断金坊 duanjin | 断墙巷战 | +2m | 6m | 低缓残丘 |
| 百足城 baizu | 窄巷网 | 0m | 4m | 近平坦（保巷战可读性） |
| 万劫三庭 santing | 中央 | 0m | 0m | 平坦（三庭已压印到 0） |

按现有 `regionBlendAt` 的 Voronoi 双区混合插值，边界有机、无接缝。

### 1.4 架构搬迁：region 模型下沉

区域模型现居 `apps/web/src/render/map/map-regions.ts`（渲染层），而 `terrain-height.ts` 在 `packages/content`（Sim 共享层）。宏观地貌由区域驱动后，**region anchors 与 blend 数学必须下沉到 `packages/content`**，否则 Sim 与 C# 拿不到同一份地貌。

搬迁范围仅限「anchor 坐标 + 混合函数」这一份纯数据/纯函数。调色板、雾色、accent 等美术项**留在渲染层不动**。

### 1.5 两个连带必改项

1. **`climateSplatAt` 的绝对高程阈值失效**
   现有 `highland = (h − 1.35) / 2.4`、`valley = h < 0.15` 是按 5.2m 平板写死的绝对高度。必须改为**相对本区基准海拔的相对高程**，否则龙脊渊整区被霜雪糊死、蛛丝峡整区判成水洼。
2. **水面从单一全局平面改为按盆地局部水体**
   现有 `TERRAIN_WATER_LEVEL_MM = −550` 是一张全局平面。深潭到 −18m 后，全局平面要么淹掉半张图、要么悬在谷底之上。详见 §3.4。

## 2. 四条底线的保证机制与验收指标

### 2.1 寻路全图连通 —— 削填走廊 + 节点高程松弛

现有 road stamp 为 `target = baseHeight(x, z) + 180mm`，即路面跟随噪声起伏；在 ±18m 地貌下会让路直接爬上山脊。改为真正的削填：

- **Pass 1 · 节点定高**：对路网节点取 `heightBeforeRoads(node)` 作初值。
- **Pass 2 · 确定性松弛**：固定 **24 轮**迭代，把每个节点朝邻居拉，直到所有边满足 `|Δh| / 边长 ≤ 0.12`。整数运算、迭代次数固定 ⇒ 结果确定、C# 可逐行照搬。
- **Pass 3 · 沿边线性插值**：路面高度在两端节点间线性插值，横向按 `halfWidth + edge` 混合。路穿山脊即**开凿**，穿谷地即**填方**，自然产生路堑与路堤。

**连通性论证**：路网图本身连通（342 条边覆盖全部 POI 锚点），走廊坡度 ≤12% 恒可走、可闪现 ⇒ 挂在路网上的任意两点连通。

**验收**：2m 栅格 BFS（单步高差上限 = 角色台阶高），断言 30 出生点、48 巢穴、24 伏石、167 宝箱点、三庭两两可达。

### 2.2 视线遮挡不能失控 —— 先测基线，再定阈值

阈值不得凭空拍定，流程为：

1. 在**当前 5.2m 平板**上跑度量，得基线阻断率（确定性采样，固定种子，10 万对点，分 12m / 25m / 40m / 60m 四档）。
2. 新地貌下重测，门槛定为「不超过基线 + X 个百分点」，X 在首次量化后与用户敲定。
3. 硬性红线（与基线无关）：**不存在半径 ≥ 25m 的连通盲域**——任一点对其 25m 邻域的可见比例不得低于阈值。

配套两处必改：

- **噪声最细八度 cell 下限 2m → 4m**，与 `GROUND_CELL_METERS = 4` 对齐。现状 Sim 高度场比渲染网格更细，二者不一致会让 LoS 被渲染里不存在的 2m 小包挡住。
- 对齐后 `TERRAIN_SIGHT_STEP_MM = 2000` 即为足量，**保持不变**（避免额外 tick 开销）。

### 2.3 出生点高度公平 —— 中位数均衡

30 个出生微位取 `heightBeforeRoads` 的**中位数**为基准，每个 pad 目标高程钳进 **中位数 ±1.5m**；`PAD_EDGE_MM` 由 4m 扩到 **40m** 做长缓过渡（最坏 12m 落差摊在 40m 上 ≈ 17°，不会出现"出生塔"）。

**验收**：30 个出生点两两高差 ≤ 3.0m；出生点 25m 内地形不得高出该点 4m 以上。

### 2.4 伏石 / 安全圈机制不变 —— 只做不变量断言

两套判定本就是纯 2D 圆，地形无从影响。所需的只是防止地貌撕裂其地面：

- 断言每个伏石圈 pad 内（r = 8.5m）高差 ≤ 0.35m。
- 断言 `MAP_SAFE_CIRCLE_PHASES` 各阶段圆心处可站立、且圆内连通（复用 §2.1 的 BFS）。
- 断言现有伏石/安全圈相关测试**逐字不改**仍通过（仅 fixtures 因高度变化重烧）。

### 2.5 验收指标汇总

| 指标 | 门槛 | 手段 |
|---|---|---|
| 全图连通 | 30 出生 + 48 巢 + 24 伏石 + 167 宝箱 + 三庭 100% 可达 | 2m 栅格 BFS |
| 路面坡度 | 全部边 ≤ 12% | 节点松弛后逐边断言 |
| 宏观坡度 | ≤ 15°（构造保证） | 采样断言 |
| LoS 阻断率 | ≤ 基线 + X pt（X 待量化后敲定） | 10 万对点确定性采样 |
| 盲域 | 不存在 r ≥ 25m 连通盲域 | 可见性洪水填充 |
| 出生公平 | 两两高差 ≤ 3.0m；25m 内无 +4m 高地 | 断言测试 |
| 伏石平坦 | pad 内高差 ≤ 0.35m | 断言测试 |
| 渲染性能 | DrawCall ≤ 145、P95 ≤ 18.4ms、60 FPS | 现有浏览器门禁 |
| 确定性 | 同 hash 重复构建几何签名一致 | 现有测试 |

## 3. POI 地貌语汇

统一原则 —— **三级可读性**：远景看剪影、中景看地貌、近景看道具。现状只有第三级。

### 3.1 伏石圈 ×24 —— 抬起的祭台

| | 现状 | 新设计 |
|---|---|---|
| 地形 | `flattenAt(r=8.5m)` 纯压平，无 bowl | **微凸台**：pad 抬高 **+0.55m**，r = 7.0m、edge = 3.0m；外接**环形浅沟 −0.35m**（r 7.0 → 10.5m） |
| 立石 | 5 根，高 1.55 ~ 2.25m | 高至 **2.4 ~ 3.2m**，其中一对加**过梁石**（三石门），另加 1 根**倒伏石** |
| 地表 | 无专属磨损 | POI 磨损遮罩接入现有 soil splat，环带踩踏色 |

凸台 + 浅沟给出「一块被抬起来的地」的远景轮廓；**三石门是这 24 个点的统一识别符号**。凸台内部严格平坦，满足 §2.4 的 ≤ 0.35m 约束。

### 3.2 小怪巢穴 ×48 —— 真碗地 + 土垄 + 授权坡道

| 环带 | 碗底深度 | 碗底半径 | 外圈土垄 | 坡道 |
|---|---:|---:|---:|---|
| 外 | **−1.8m** | 6.0m | +0.6m | 2 条 |
| 中 | **−2.8m** | 7.0m | +0.9m | 2 条 |
| 内 | **−4.0m** | 8.0m | +1.2m | 2 条 |

**关键手法**：碗壁**故意做陡**（戏剧性），连通性不靠放缓坡度，而靠**授权坡道**——每个巢穴开 2 条 ≤12% 的坡道缺口，方向**对齐 `MAP_NEST_LINKS` 的迁移路径**。与现有高台 ramps 同一套语言，怪物迁移与玩家进攻路径在地形上被显式表达。

**剪影保证**：土垄高 0.6 ~ 1.2m，图腾杆/栖杆抬到 **3.4 ~ 4.8m**，必然高过垄线；MEL 洞口由"平地上的半球"改为**开在碗壁上的真洞口**。

### 3.3 Boss 巢穴 —— 地形本身即竞技场

**龙宫 ×5（水庭）**
- 下沉盆地 **−5.0m**，庭底 r = 16m，环形崖壁抬至 **+2.0m** 垄顶
- **3 条 12% 坡道缺口**，方向**对齐已有的三向门楼**（复用现有数据，不新增）
- 庭底注水：局部水面在庭底 **+1.2m** ⇒ 环形浅水庭（§1.5 局部水体的首个落地点）
- 远景剪影：现有外侧双层殿阁抬到崖壁顶，配合区域雾色成为地标

**精英斗场 ×4**
- 下沉 **−3.5m**，场底 r = 13m，**六角崖壁**
- **2 条对向通路**——现有设计本即"保留双向通路的六角斗场"，此次将其地形化

**核心 Boss（三庭庭心）—— 不做下沉**
三庭 court stamp 目标恒为 0，且真源要求"庭心保持无遮挡供核心 BOSS 与终局使用"。**不碰庭心**，改在庭外圈加**三级环形阶梯看台（+1.5m）**：仪式感靠台阶，终局判定一行不改。

### 3.4 局部水体系统

替换 `TERRAIN_WATER_LEVEL_MM` 单一全局平面，改为**水体表**：龙宫庭底 ×5、龙脊渊深潭、蛛丝峡谷底汇水、迷魂田浅盆。每个水体为 `{中心, 半径, 水位}`，由地貌确定性导出，渲染层按盆地生成水面片。

### 3.5 小地图同步升级

加 **hillshade 晕渲**（离屏静态层预渲染，零运行时开销）+ POI 分级图标（伏石 / 巢穴按环带 / Boss）。

## 4. 渲染质感与视角靠拢

### 4.1 正交 → 透视

现状：

```
new THREE.OrthographicCamera(-20, 20, 12, -12, 0.1, 180)
CAMERA_VIEWS.standard: offset [14, 16, 14]  ⇒ 俯角 38.9°
```

正交投影下没有近大远小、地平线、远近山峦叠压与大气透视——即使地形做到 ±18m，仍会被压扁成色块图。

| | 现状 | 新设计 |
|---|---|---|
| 投影 | Orthographic | **Perspective，FOV 30°（低 FOV）** |
| 俯角 | 标准 38.9° | 标准 **32°** / 近景 **26°** / 战术 **48°** |
| 相机距离 | offset 模长 24.7m | ~26m（低 FOV 补偿，画面尺度基本不变） |
| 远平面 | 180 | **600**（吃下远山剪影） |

**低 FOV 是关键折中**：30° FOV 的透视畸变极小，30 个角色的体型一致性与技能圈可读性基本保住竞技水准，同时解锁纵深、地平线、大气透视。技能范围圈与脚底环是世界空间地面几何，透视下照常正确；兴趣管理走相机视锥，无需改判定。

### 4.2 连带必改

1. **阴影视锥 ±38m 不够** —— 改为 2 级 CSM 或按相机距离动态收缩。
2. **遮挡淡出压力上升** —— 俯角降至 26 ~ 32° 后遮挡概率显著上升；扩容现有 `flora-occlusion.ts` 与 `map-occlusion.ts`，不新建模块。
3. **移动端竖屏 390×844 独立配置** —— 竖屏 + 低俯角前向可视距离过短，按视口给独立档（竖屏 38°、横屏 32°）。

### 4.3 陡坡三平面投影

现有地面 UV 为世界米平面投影（`x/15, z/15`），在新的崖壁与碗壁上会拉成条纹。陡坡改走 **triplanar**，并按坡度混入岩层材质。**与地形同批交付，不可拆分**。

### 4.4 大气与光

- **高程雾**：在现有按区雾密度之上叠加高度衰减 ⇒ 谷底积雾、山脊出云。
- **远景分层**：`beyond.ts` 由两圈山峦剪影扩为 **3 层**，按距离递增去饱和 + 提亮混入雾色，形成空气透视。
- **植被逆光边缘光**：树冠加轻微 rim，配合已有对向冷补光。

### 4.5 植被按地形分布

在现有按区域密度散布之上，新增地形驱动规则：

| 规则 | 效果 |
|---|---|
| 坡度 > 25° 不长乔木，改碎石/苔藓 | 崖壁干净，山形可读 |
| 相对高程 > 阈值 落雪线 | 龙脊渊山顶自然雪冠 |
| 水体 3m 内长芦苇/湿生草 | 蛛丝峡、迷魂田湿地感 |
| 碗地内壁密植低矮灌木 | 巢穴视觉封闭 |

配合 §4.4 高程雾，**同一套 flora 资产**即可读出雪原/沼泽/金秋三种面貌，无需新美术。

### 4.6 水体表现

局部水体落地为：深度染色 + 岸线泡沫带 + 低成本屏幕空间反射（移动端降级为反射天空色）。龙宫环形浅水庭为最重展示面。

### 4.7 性能守恒

| 项 | 增量 |
|---|---|
| 地面 | 顶点数不变（4m 网格），仅 y 变化 —— **0** |
| POI 地貌 | 全在高度函数内 —— **0 新几何** |
| triplanar / 高程雾 / rim | 着色器内 —— **0 DrawCall** |
| 远山第 3 层 | +1 DrawCall |
| 水体 | 1 全局面 → ~9 局部面，合批后 **+1~2 DrawCall** |
| CSM 第 2 级 | +1 shadow pass |

预算：现状 135 DrawCall / P95 18.4ms / 60 FPS ⇒ 目标 **≤ 145 DrawCall，P95 ≤ 18.4ms 不退**。

## 5. 迁移重烧流程与风险

### 5.1 地形版本号独立于几何哈希

`MAP_GEOMETRY_HASH = dc80a9ec2b7b9ff4` 是编译后地图几何的哈希，而地形高度场是其上的函数（并以其为噪声种子）。新增：

> **`TERRAIN_PROFILE_VERSION`**，与 `mapGeometryHash` 并列进入快照与状态哈希。

收益：地图权威几何 JSON 一行不改 ⇒ `npm run map:authority` 保持 `dc80a9ec2b7b9ff4` 绿灯，地形迭代不污染地图权威验证；同时地形改版被状态哈希如实记录，对拍不会静默漂移。

### 5.4 风险清单

| 风险 | 影响 | 应对 |
|---|---|---|
| LoS 阻断率超预算 | 战斗节奏被破坏 | P5 量化后若超，**优先降宏观振幅**（22m → 16m）而非改判定 |
| 透视化伤竞技可读性 | 最大主观风险 | FOV 压到 30° 已最小化；P7 单独出图评审，不满意可退回正交且**不影响 P0–P6 任何成果**（相机是独立层） |
| 移动端竖屏可视距离不足 | 390×844 不可玩 | 竖屏独立俯角 38°；纳入现有移动端门禁 |
| 巢穴碗地成"卡位陷阱" | 玩家掉进去出不来 | 2 条授权坡道 + BFS 断言碗底可达；碗深可单点回调 |
| 节点松弛不收敛 | 路面坡度超标 | 固定 24 轮 + 逐边硬断言；未达标报错而非静默 |
| 重烧期对拍长时间红灯 | Unity 主线阻塞 | `TERRAIN_PROFILE_VERSION` 让红灯可归因；阶段一集中做完再一次性同步 C# |
| 陡坡纹理拉伸 | 新崖壁穿帮 | triplanar 与地形同批交付（P6 不可拆） |
| 性能回退 | 掉出 60 FPS | 逐步验收；水体/CSM 是唯二增量，可单独降级 |

### 5.5 单一回退旋钮

整套设计收敛到**一个主旋钮**：**宏观振幅系数**（默认 1.0）。若 LoS、性能或手感任一不达标，调低该系数即可整体退回更平缓的地形，无需回滚任何代码。**相机是第二个独立旋钮。**
