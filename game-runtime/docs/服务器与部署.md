最后更新：2026-09-06  
适用仓库：`https://github.com/cryangle0/sanmingwuchang.git`（本机目录名仍是 JourneyWestGreatBrawl）  
线上站点：https://fanavatar.org/

另一台电脑只要 `git pull` 再 `npm install`，就能跑 Web 客户端和本地权威服。角色/地图/植被的 **Web GLB** 都在仓库里。Unity 源 FBX、OSS 密钥、SSH 私钥不进 Git，需要单独拷。

早期域名开通记录见 [`服务器/fanavatar.org-setup.md`](../服务器/fanavatar.org-setup.md)（2026-08-06，当时站点还是占位页）。**业务怎么跑、怎么发版以本文为准。**

## 1. 系统怎么拆

线上不是「整站都在那台 ECS 上」，而是三层：

| 层 | 谁提供 | 做什么 |
|----|--------|--------|
| 浏览器页 + 静态资源 | 阿里云 OSS + CDN | `index.html`、带 hash 的 JS/CSS、音频、Web 模型 GLB、英雄头像 |
| 权威对局 | 新加坡 ECS 上的 Node | 20 Hz 确定性模拟，WebSocket `/match`，HTTP `/health` |
| 入口 | 同机 Nginx | HTTPS、把 `/match` 反代到本机 8787、把头像走同源 `/jwgb-assets/` |

浏览器打开 https://fanavatar.org/ 时：

1. Nginx 吐本机 `/var/www/fanavatar.org/index.html`（每次发版覆盖）。
2. HTML 里的 script/css 指向 CDN：`https://vibe-files.aigcresearch.com/AIGame/JourneyWestGreatBrawl/current/...`
3. 角色 FBX 纹理走 `.../models/v1/`（转换前的 CDN 模型；运行时 Web 用的是 `current/` 里的 GLB）。
4. 对局连 `wss://fanavatar.org/match` → Nginx → `127.0.0.1:8787`。
5. 头像走 `https://fanavatar.org/jwgb-assets/assets/heroes/...` → Nginx 再去拉 CDN `current/`，避免跨域读像素失败。

本地开发默认 `npm run dev:web`，模型在 `apps/web/public/models/`。Vite 会把缺的角色 FBX 代理到同一套 CDN。`?mode=local` 不连线上服，模拟跑在浏览器里。

| `/opt/jwgb-web/current/server.mjs` | 打包后的权威服 |

| `/etc/letsencrypt/live/fanavatar.org/` | 证书 |

`jwgb-web.service` 要点：用户 `jwgb-web`，`HOST=127.0.0.1`，`PORT=8787`，`Restart=always`，工作目录 `/opt/jwgb-web/current`。

常用检查：

```bash

curl -fsS http://127.0.0.1:8787/health

tail -f /var/log/nginx/error.log

```

### 3.2 故意不进 Git 的

| 内容 | 原因 | 另一台电脑怎么办 |
|------|------|------------------|
| `node_modules/`、`dist/` | 构建产物 | `npm install` / `npm run build` |
| `deploy/oss-credentials.txt` | 密钥 | 从本机拷到相同路径 |

## 4. 发到线上（标准路径）

只在装了 SSH 私钥和 OSS 凭据的机器上做。脚本是 Windows PowerShell。

### 4.1 一次性准备

1. Node.js 22+，能跑 `npm` / `npx`。
2. 私钥：`C:\Users\xinzh\.ssh\id_ed25519`（路径写死在脚本里；换机要么放同一路径，要么改 `tools/deploy/deploy-web-demo.ps1` 的 `$sshKey`）。
3. 凭据文件 `game-runtime/deploy/oss-credentials.txt`，格式：

```text
OSS_ACCESS_KEY_ID=...
OSS_ACCESS_KEY_SECRET=...
OSS_ENDPOINT=...
OSS_BUCKET_NAME=...
OSS_BASE_PATH=AIGame
OSS_CDN_DOMAIN=vibe-files.aigcresearch.com
```

仓库里有一份无密钥的 `deploy/oss-credentials.example.txt`。

4. 能 SSH 上 `root@47.84.61.45`。

### 4.2 发一版

在 `game-runtime/`：

```powershell
# 先自测
npm run typecheck
npx vitest run

# 完整发版：构建 → 上传 OSS（含 current + releases/时间戳）→ scp 小包到 ECS → 重启服务
npm run deploy:web
```

只改了 JS/CSS、没改角色 FBX 时可以：

```powershell
npm run deploy:web -- -SkipModels
```

`-SkipModels` 跳过 `models/v1/` 的 FBX 扫描。`current/` 里的 Web GLB 仍会随 `dist` 上传。

脚本实际做的事（`tools/deploy/deploy-web-demo.ps1`）：

1. 读 OSS 凭据进进程环境。
2. 设  
   `JWGB_WEB_BASE_URL=https://vibe-files.aigcresearch.com/AIGame/JourneyWestGreatBrawl/current/`  
   `VITE_MODEL_BASE_URL=.../models/v1/`  
   `VITE_PORTRAIT_BASE_URL=/jwgb-assets/`  
   `VITE_ASSET_VERSION={yyyyMMddHHmmss}`
3. `npm run build`（web + server）。
4. `tsx tools/deploy/upload-web-assets.ts`：dist 传到 `releases/{id}/` 再覆盖 `current/`；可选上传 `models/v1/`。
5. 打一个很小的 tar：`server.mjs`、`package.json`、`jwgb-web.service`、nginx 配置、`index.html`。
6. `scp` 到 `/tmp/jwgb-web-deploy-{id}.tar.gz`，SSH 远程：安装 Node 22（若无）、写入 `/opt/jwgb-web/current`、`npm install --omit=dev`、覆盖 nginx 与 index.html、`systemctl restart jwgb-web`、`nginx -t && reload`、打 `/health`。

成功时终端会印：

```text
deployed release 20260903164226
Web demo deployed: https://fanavatar.org/
```

### 4.3 发完验证

```powershell
npm run verify:web:production
npm run verify:web:browser
```

浏览器请 **强制刷新**（Ctrl+F5）。入口 HTML 在 ECS 上，JS 文件名带 hash；旧标签页可能还拿着上一包 `index.html`。

### 4.4 只上传、不上机

```powershell
# 需要已 build，且环境变量或 oss-credentials.txt 已就绪
npm run web:oss:upload
```

这不会重启 ECS 上的 Node，也不会换 `/var/www/fanavatar.org/index.html`。日常发版用 `deploy:web`，不要只跑这一步。

### 4.5 回滚思路

- 静态资源：CDN 上仍有 `releases/{旧ReleaseId}/`。把那一版的 `index.html` 拷回 `/var/www/fanavatar.org/index.html`，或把该 release 再同步到 `current/`。
- 权威服：用当时的 `apps/server/dist/server.mjs` 再 scp 到 `/opt/jwgb-web/current/server.mjs` 后 `systemctl restart jwgb-web`。仓库里没有自动回滚命令，需要对一下发版时间戳。

## 5. Nginx 行为（和发版的关系）

源文件：`deploy/nginx/fanavatar.org.conf`，每次 `deploy:web` 覆盖线上。

- `/` → 本机 `index.html`（SPA）
- `/match` → `http://127.0.0.1:8787/match`（WebSocket Upgrade）
- `/health` → `http://127.0.0.1:8787/health`
- `/jwgb-assets/` → 反代 CDN `current/`（头像同源）

改反代或证书相关配置：先改仓库里的 conf，再发一版；不要只在服务器上手改，下次发版会被盖掉。

## 6. 另一台电脑清单

要继续 **改 Web 游戏**：

1. 装 Node 22+。
2. `git clone` / `git pull` `main`。
3. `cd game-runtime && npm install && npm run dev:web`。
4. 需要联机时再 `npm run dev:server`。

要继续 **往 fanavatar.org 发版**，额外：

1. OSS 凭据文件放到 `game-runtime/deploy/oss-credentials.txt`。
2. 能 SSH 的私钥，路径对上脚本或改脚本。
3. 在 `game-runtime` 执行 `npm run deploy:web`。

要继续 **Unity 迁移 / 重转角色 FBX**：

1. 另拷被 gitignore 的 `game-runtime/unity/Assets/`（以及根目录美术包，若你本机有）。
2. Web 对局本身不依赖这些目录。
