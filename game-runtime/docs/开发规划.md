# 《三命无常》开发规划

文档版本：0.2.0
日期：2026-07-24
规划方式：先完成 Unity 迁移 Gate，再在 Unity 生产路径扩完整内容

## 1. 开发原则

- 每个里程碑必须提供可运行结果和自动化证据。
- 不以文件数量或代码行数代表进度。
- 规则、数据、客户端、服务端和测试同步交付。
- 先解决共享内核和工具链，再生产 38 英雄完整内容。
- 任何影响公平的信息不能因性能档位而消失。
- 每个 P0 冲突在进入对应系统开发前必须获得明确裁决。
- 当前 TypeScript 实现保留为行为 Oracle，不在迁移期删除。
- 除缺陷修复、Fixture、协议边界和迁移工具外，暂停继续扩大 TypeScript 玩法面。
- “极致性能”必须由目标硬件、真机热稳态和服务器压力测试证明。

## 2. Unity 迁移优先级

产品里程碑 M0 至 M8 继续表达需要交付的玩法和生产能力，但实施顺序从
2026-07-24 起增加 U0 至 U7 迁移主线。U0 至 U5 优先于继续扩大 M2 至 M7 的
TypeScript 实现。

| 迁移阶段 | 目标 | 主要验收 |
|---|---|---|
| U0 工具链 | Unity 6.3 LTS 工程、包锁和三类批处理构建 | Windows、Android 空壳和 Linux Server 可重复构建 |
| U1 压力基线 | 先做 30 + 123 + 270 合成压力场 | 固定设备和 4 vCPU 服务器输出 P95/P99 |
| U2 确定性基础 | 移植整数数学、ID、RNG、哈希和回放 | TS/C# 核心向量和 1000 种种子逐 tick 一致 |
| U3 M1 等价 | 移植当前 M1 规则纵向切片 | 现有行为合同、完整 BOT 对局和状态哈希闭合 |
| U4 Unity 客户端 | URP、HUD、输入、资源、预测和插值 | Android、iOS、Windows 固定场景真机性能 |
| U5 权威联机 | Netcode、Dedicated Server、恢复和 30 客户端 | tick、带宽、恢复和结算门槛通过 |
| U6 完整迁移 | 在 Unity 路径实现 M3 至 M7 | 地图、PVE、经济、终局、内容和全量压测 |
| U7 发布切换 | 三端发布、灰度、回滚和 TS 退役 | 所有发布 Gate 获得真实证据 |

详细版本、性能预算、时间估算和 Go/No-Go 见 `docs/Unity迁移规划.md`。

## 4. M0 工程基线

### 范围

- npm workspace。
- TypeScript strict。
- Biome、Vitest、Vite 和 esbuild。
- `core`、`content`、`protocol`、`sim` 四个共享包。
- Three.js Web 客户端。
- Node WebSocket 服务端。
- 20 Hz 本地 Sim 宿主。
- 第一版 HUD、键鼠和触控输入。
- 第一版三命链和雷暴。

### 验收

- `npm run typecheck` 通过。
- `npm test` 通过。
- `npm run build` 通过。
- 浏览器画面非空。
- 桌面和移动视口无 UI 重叠。
- 同种子和输入的状态哈希一致。

## 5. M1 确定性战斗切片

### 内容

- 三名代表英雄：孙悟空的近战爆发和被动放大、铁扇公主的风墙和弹道分割、牛魔王的持续近身范围伤害。
- 三个通用主动：D6 闪现、D22 铁布衫、D21 冰棺。
- 四个被动：B06 暴击、B17 护盾、B19 假死、B20 复活。
- 四件装备：W1 精铁棍、W2 粗布战衣、G1 九转金丹、G10 金箍棒。

截至 2026-07-23，上述代表英雄、主动、被动和装备已经形成可运行、可回放的纵向切片。B06/B17 的五级质变、H009 白名单翻倍、W1/W2/G10 有效属性和远程弹道预算均已有自动化证据；这不代表完整 44 被动、48 装备或完整 M1 已经完成。

### 系统

- 普攻前摇、攻击间隔、释放快照和逐 tick 连续扫掠弹道。
- 伤害 14 阶段。
- 护盾和伤害类型。
- 控制与免疫。
- 三条命和掉落。
- 普通天劫和灭世雷暴。
- 输入记录和回放。

### 验收

- 1000 次随机种子回放无哈希漂移。
- 本地 Sim 与关闭墙钟驱动的真实 WS 权威房间，对相同根种子、加入顺序和输入带产生相同最终状态哈希。
- 同 tick 双淘汰按稳定实体 ID 全部提交，不因容器遍历顺序遗漏。
- 假死、被动复活、金丹和耗命顺序测试通过。
- D6 的 15 米位移、零瞄准回退、1.500/1.501 米穿墙边界、非法终点和回放哈希测试通过。
- D21 的 80 tick 自锁、七类伤害归零、护盾不消耗、计时继续和输入恢复测试通过。
- 长弓/连弩弹速、角色首次接触、风墙阻挡、目标淘汰销毁和所有者死亡后归属测试通过。
- 客户端不包含伤害决定逻辑。
- 一场加速 BOT 对局能产生唯一胜者。

截至 2026-07-24，代表战斗机制、客户端权威边界、加速 BOT 完整对局、唯一胜者/
平局和整局回放已经通过当前 TypeScript 基线。完整 14 阶段伤害和并列冠军规则仍未
闭合。Unity U3 必须重新获得对应证据，不能继承“已通过”状态。

## 6. M2 网络房间

### 内容

- WS 首包鉴权。
- 房间创建和加入。
- 20 Hz 输入。
- 10 Hz 差量快照。
- 事件通道。
- 自身预测和服务端重校正。
- 其他实体插值。
- 心跳、弱网和断线接管。
- 快照分块、确认和完整性校验。

### 验收

- 两个浏览器完成真实联机。
- 30 个机器人客户端保持稳定房间。
- 120 秒内重连不复制实体、物品或输入。
- 非法输入、超频和大包被拒绝。
- 网络 P95 和快照大小进入预算。

迁移约束：

- 当前 JSON v7、`ws` 和浏览器 ClientWorld 只作为语义与 Fixture 来源。
- 生产 M2 在 U5 使用 Netcode for Entities、Unity Transport 和 Linux Dedicated Server。
- 插值、有限移动预测、差量和兴趣域直接在 Unity 路径完成，不继续扩大 Web 产品路径。

## 13. 测试策略

- 纯规则优先单元测试。
- 每个系统使用确定性输入向量。
- 每个已修复缺陷保留回归测试。
- TypeScript 导出 Golden Fixtures，C# 报告首个漂移 tick。
- 当前协议编码和解码继续成对测试，Unity Ghost/消息另建兼容和边界测试。
- Dedicated Server 使用 30 个 Headless Client 集成和持续压力测试。
- 当前浏览器 Playwright 证据只证明 Web Oracle；Unity 使用固定场景截图和像素回归。
- 真机使用固定战斗场景做性能对比。
- 性能报告必须记录 commit、Editor、包版本、构建参数、设备和完整分位数。
- Unity 包或 Editor 升级必须重跑确定性、性能和三端构建。
- 每个里程碑更新 `开发进度.md`。

## 14. 风险排序

### P0

- 规则投影冲突。
- 单位和舍入不闭合。
- 地图重复边和墙体冲突。
- 没有内容编译器。
- 没有权威回放证据。

### P1

- 30 人终局表现和网络压力。
- 270 理论召唤物。
- 移动端内存和热降频。
- 经济极端构筑。
- 资产版权和生产进度。
- Unity/DOTS/Netcode 学习、版本和调试成本。
- ARM64、x64 和并行提交顺序导致的确定性漂移。
- iOS 必须准备 macOS、Xcode 和真机发布环境。

### P2

- 局外系统和商业化。
- 社交、战报和长期运营功能。
- 复杂美术后处理和高端表现。
